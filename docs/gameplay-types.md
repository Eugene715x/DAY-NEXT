# Назначения зданий, природные биомы и ресурсы

`building-roles.js` задаёт игровые назначения каждого дома, а `gameplay-types.js` сохраняет классификацию исходных сведений и общие профили возможных ресурсов. Геометрия и теги OSM не заменяются назначением для игры.

- `BUILDING_CATEGORIES` — 12 цветовых категорий: жильё, магазины, еда, медицина, образование, производство, склады, транспорт, общественные здания, службы, гостиницы и руины.
- `BUILDING_ROLES` — подробные роли вида `role.house`, `role.shop_food`, `role.shop_hardware`, `role.school`, `role.warehouse`, `role.factory`, `role.airport`, `role.hangar`.
- `BUILDING_TYPES` — исходные типы назначения вида `building.house`, `building.medical` или `building.unknown`.
- `BIOME_TYPES` — общий справочник типов. Текущую карту покрывают непересекающиеся природные, городские и водные биомы; `biome.city` — городской фон, `biome.seasonal_river` — сезонное русло. Прежние служебные типы сохранены для совместимости исходных данных.
- `RESOURCE_PROFILES` и `RESOURCE_KINDS` — общие списки категорий потенциальных ресурсов.

## Назначение и происхождение

`createBuildingAssignments(world)` возвращает клонированные здания с полем `gameplayAssignment` и отчёт. Каждый дом получает `roleId`, `roleName`, `categoryId`, цвет и значок, ссылки `resourceProfileIds`, состояние и происхождение назначения.

`roleOrigin` различает `mapped` (теги здания или подходящие метки внутри контура), `context` (территория учреждения) и `gameplay` (устойчивое назначение для игры). Составное здание с несколькими метками может стать объектом смешанного назначения. Внутренние дворы исключаются при поиске меток. Адрес или совпадение имени сами по себе не подтверждают назначение.

`sourceFactType` хранит результат `classifyBuilding()`. Поэтому фактическое `building=yes` остаётся неуточнённым, даже когда игровая роль названа жилым домом или мастерской. Подтверждённое назначение имеет приоритет перед обобщённой игровой ролью. Состояние руин и назначение независимы: разрушенная больница может сохранять медицинскую роль.

## Общие профили

Чтобы изменить возможные ресурсы сразу для всех домов одного назначения, отредактируйте `resourceProfileIds` роли или общий `candidateResourceIds` соответствующего профиля. Объекты хранят ссылки на профили.

```js
const { features, report } = createBuildingAssignments(world);
const role = features[0].gameplayAssignment;
const profiles = collectResourceProfiles(role, classifyBiome('desert'));
const possibleResources = collectResourceCandidates(role);
```

`collectResourceProfiles()` и `collectResourceCandidates()` также принимают описание здания с вложенным `gameplayAssignment`, объединяют ссылки без повторов и не создают предметы. Настройки не описывают реальное содержимое домов. Механика лута, количество и вероятности пока не реализованы.

Каталоги неизменяемы во время игры; результаты классификации и назначения содержат независимые массивы. Типы, категории и назначения каждого дома входят в автономный ZIP.

`zonesAt(x, y)` возвращает один биом земли независимо от видимости слоя. Пунктирные промежутки сезонного русла относятся к тому же биому русла. Его профиль `profile.outdoors` не добавляет питьевую воду; профиль постоянной воды остаётся отдельным. `biome-map.js` сохраняет происхождение исходных участков и вырезает области более высокого приоритета из остальных. Подробности: [biomes-v13.md](biomes-v13.md).
